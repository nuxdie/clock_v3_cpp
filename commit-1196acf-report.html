What changed in main.cpp at commit 1196acf

Commit 1196acf1 — "Refactor code structure for improved readability and maintainability" Author WiegerWolf Date Wed 22 Jul 2026 Version 0.2.1 → 0.3.0 Diff main.cpp ~1071 lines touched

Despite the modest commit message, this is a ground-up rewrite of the visual layer. The old app was a photo-background clock with falling snow and a Russian weather line. The new app is a flat, theme-aware "modern layout" clock with a hand-drawn weather strip and a rain forecast chart. This report walks through it feature by feature, explaining the C++ patterns and the traps for each.

1The big picture: what was deleted vs. added

Removed entirely:

  • SnowSystem class (~130 lines) — a parallelized particle system.
  • Bing background-image downloading (FetchBackgroundImage, RenderTextureCover, the "object-fit: cover" logic).
  • The BingImage, CurrentWeather, WeatherData, LlmMessage, LlmChoice, LlmResponse structs.
  • The Russian weather vocabulary (WEATHER_CODE_RU, getWindspeedType, Russian weekdays/months).
  • FPS / frame-timing machinery (UpdateTiming, deltaTime, fps).

Added:

  • A color/theme system (Col, Palette, mix, mixPalette, dayFactor) that crossfades between a dark "night" theme and a light "day" theme.
  • Weather icons (PNG assets) and an Icon enum.
  • Two text-rendering helpers: Label (cached text texture) and TrackedLabel (per-glyph rendering for letter-spacing).
  • A rain forecast bar chart (DrawRain) fed by Open-Meteo's minutely_15 precipitation data.
  • A screenshot mode (APP_SHOT env var) for headless verification.

The header swap is the tell: font_data.h → assets_fonts.h + assets_icons.h.

Learning point

Include the headers you use, and remove the ones you don't. Every deleted include here is a fingerprint of a deleted feature: <execution>, <random>, <numbers>, <ranges> all vanished with the snow; <map> with the Russian lookup; <functional> with the std::function layout callbacks. using namespace std::string_literals; was dropped too — the new code has no "…"s literals.

3Configuration: from font sizes to a layout system

Old Config had font_big_size, font_normal_size, num_snowflakes. New Config replaces them with a block of layout constants in logical pixels:

constexpr float pad_x = 56.0f;
constexpr float date_baseline = 84.0f;
constexpr float time_baseline = 362.0f;
// ...

Pattern — constexpr: compile-time constants baked into the binary, with no runtime cost and no global mutable state. This is the modern, type-safe replacement for #define, and it respects scope (it lives in namespace Config).

Why float not int? The new rendering uses SDL_FRect (float rectangles) everywhere and does sub-pixel positioning like baseline - ascent * 0.42f. Keeping layout math in float avoids scattering (float) casts.

4The color system — constexpr functions and aggregate structs

This is the most "new C++" part of the commit. Read it slowly.

struct Col {
  float r = 0, g = 0, b = 0, a = 255; // 0..255, kept as float for cheap mixing
};
constexpr Col mix(const Col &a, const Col &b, float t) {
  return {a.r + (b.r - a.r) * t, /* ... */};
}
  • Default member initializers (float r = 0, …): every Col is fully defined even as Col c;. No uninitialized-memory bugs.
  • Aggregate / brace initialization: return {…}; builds a Col without naming the type. Col{13, 20, 29} fills r,g,b and leaves a at its default 255 — that's why the palette tables read so compactly.
  • constexpr function: mix can run at compile time, so constexpr Palette kDark{…} exists in the binary with zero startup cost.
  • Linear interpolation ("lerp"): a + (b - a) * t — t=0 gives a, t=1 gives b. Used for individual colors and, one level up, for whole palettes in mixPalette.
Gotcha

Colors are stored as float 0–255, not the 0.0–1.0 that graphics code often uses. That's why you later see (Uint8)c.r casts when handing colors to SDL, and c.r / 255.f conversions when SDL wants normalized floats (SDL_FColor in fillCircle/drawGradient). Mixing the two conventions is a classic "why is everything black / washed out" bug. The code converts correctly at each SDL boundary — but it's easy to break later.

dayFactor returns 0 at night, 1 in daytime, and a linear ramp during 07:00–08:00 and 18:00–19:00. That one float drives the whole theme crossfade via mixPalette(f). Clean separation: one function decides "how much day is it," another decides "what do colors look like at that amount of day."

5Weather logic rewritten: std::map → switch

Old code looked up weather descriptions in a std::map<int, std::string_view>. New code uses plain switch statements (iconFor, conditionText), and the language changed from Russian to English.

Why is this an improvement?

  • A std::map allocates nodes on the heap and does an O(log n) tree lookup. A switch over integers compiles to a jump table — faster, no allocation, values live in code rather than a runtime-built container.
  • iconFor collapses many WMO codes into a small Icon enum (all snow codes → Icon::Snow), with a default: arm handling "everything else is rain."

enum class Icon is a scoped enum — you must write Icon::Snow, never bare Snow. That blocks name collisions and accidental int conversions.

The COUNT trick

enum class Icon { ClearDay, …, COUNT }; — because values auto-number from 0, COUNT equals the number of real entries, so std::array<TexturePtr, (std::size_t)Icon::COUNT> sizes an array to exactly one slot per icon. It only works if COUNT stays last and nobody assigns explicit values — add a new icon before COUNT and everything resizes automatically.

6parseTs and manual C-string parsing

std::time_t parseTs(const std::string &s) {
  std::tm tm{};
  int Y, M, D, h, mi;
  if (std::sscanf(s.c_str(), "%d-%d-%dT%d:%d", &Y, &M, &D, &h, &mi) != 5) return 0;
  tm.tm_year = Y - 1900;
  tm.tm_mon  = M - 1;
  /* ... */
  tm.tm_isdst = -1;
  return std::mktime(&tm);
}

This parses an ISO timestamp like 2026-07-24T13:45 into a time_t. A pile of classic C date traps — all handled correctly:

  • std::tm tm{} — the {} zero-initializes the struct. Skip it and fields like tm_sec hold garbage that mktime will happily use.
  • tm_year is "years since 1900" and tm_mon is 0-based (0 = January). Hence Y - 1900 and M - 1 — the #1 date bug in C.
  • tm_isdst = -1 tells mktime "I don't know if DST applies; figure it out." Hard-coding 0 or 1 shifts your time by an hour half the year.
  • sscanf return check: != 5 means "did all five fields parse?" If not it returns 0 instead of a garbage time — the safe way to use the error-prone sscanf.

It exists so FetchWeather can skip precipitation buckets already in the past (… < now - 450, i.e. within the last 7.5 minutes).

7Text rendering: Label and TrackedLabel

This replaces the old inner TextLabel struct. Understanding why it changed is the heart of the "readability/maintainability" claim.

The old approach (TextLabel)

Each label bundled text + texture + a std::function<SDL_FRect(w,h)> layout callback. Every frame, UpdateTextures() recomputed positions by calling those lambdas, chaining them (weatherBottom = weatherLabel.rect.y + …), and baked a black drop-shadow into every draw. Problems:

  • std::function is a heavyweight, type-erased wrapper — it can heap-allocate and adds an indirect call per label. Overkill when layout is fixed.
  • Positions were relative to each other, so one label's size affected the next's — fragile chaining.
  • Color was fixed white + shadow; you couldn't cheaply re-tint for a theme.

The new Label

struct Label {
  TexturePtr tex;  float w = 0, h = 0;  int ascent = 0;
  std::string cache;  int wrapCache = -1;

  void set(SDL_Renderer *r, TTF_Font *f, const std::string &s, int wrap = 0) {
    if (s == cache && tex && wrap == wrapCache) return; // ← skip if unchanged
    /* ... render white texture ... */
  }
  void drawTop(/*...*/)   // draw at top-left
  void drawBase(/*...*/)  // draw so the *baseline* lands at baselineY
};
  • Render white once, tint at draw time. The texture is always white; color/alpha are applied via SDL_SetTextureColorMod / SDL_SetTextureAlphaMod when drawing. A theme crossfade or a blinking colon then costs nothing — no re-rasterizing glyphs. That's why the old baked-in shadow had to go.
  • The cache guard lets set() be called every frame but only rasterize when the string actually changes. The clock only re-rasterizes when the minute ticks.
  • Baseline-aware drawing. drawBase places text so the typographic baseline sits at a given Y using TTF_GetFontAscent — how the temperature number and its °C unit (different sizes) share one baseline. You position by baseline, not by the top of the box.
  • RAII smart pointers (TexturePtr, SurfacePtr): the SDL texture frees automatically on destruction/reset. No manual SDL_DestroyTexture.

TrackedLabel — solving a real limitation

// Per-glyph rendered run so we can apply letter tracking (SDL_ttf has none).

SDL_ttf can't do letter-spacing. So this renders each character to its own little texture and lays them out with a configurable tracking gap. Used only for the spaced-out uppercase date header. Newbie-relevant details:

  • UTF-8 handling (utf8Len): a UTF-8 character is 1–4 bytes; utf8Len inspects the lead byte's high bits to decide how many to grab (s.substr(i, n)). Treating one byte as one character is a very common bug this avoids.
  • std::move(g) when pushing into the vector: G owns a move-only TexturePtr, so you must move, not copy. Forgetting it fails to compile — the language protecting you.
  • Spaces have no pixels: TTF_RenderText_Blended returns a zero-width surface for a space, so the else branch falls back to TTF_GetStringSize just for the advance width — or spaces would collapse.
  • totalW = x > 0 ? x - tracking : 0; — tracking is added after every glyph, so the last one over-counts by one gap; this subtracts it back. A subtle off-by-one.

8Font & icon loading — lambdas and DIY typography

auto open = [](const unsigned char *data, unsigned int len, float size) {
  return FontPtr(TTF_OpenFontIO(SDL_IOFromConstMem(data, len), true, size));
};
fTime    = open(SpaceGrotesk_Medium_ttf, SpaceGrotesk_Medium_ttf_len, Config::time_size);
fTempNum = open(SpaceGrotesk_Medium_ttf, SpaceGrotesk_Medium_ttf_len, 46.0f);
  • Local lambda to kill repetition. The old code repeated the full open-from-memory incantation three times; the lambda names it once. Nine fonts are opened from three embedded typefaces (Space Grotesk, Inter, Victor Mono) at various sizes.
  • The true argument means "close the IO stream automatically" — a resource detail easy to get wrong by hand.
  • Fonts are embedded in the binary (byte arrays in assets_fonts.h), loaded from memory not a file — so the app needs no font files at runtime (relevant to the Raspberry-Pi deploy).

Glyph feature-detection:

windUnit = TTF_FontHasGlyph(fUnitSm.get(), 0x2044) ? "m\xE2\x81\x84s" : "m/s"; // m⁄s
approx   = TTF_FontHasGlyph(fRainCap.get(), 0x2248) ? "\xE2\x89\x88"   : "~";   // ≈

It asks the font "do you have the fraction-slash / the ≈ glyph?" and uses the pretty character if so, else an ASCII fallback. The "\xE2\x81\x84" is the UTF-8 byte encoding of U+2044 written as an escaped literal — a portable way to embed a Unicode character regardless of the source file's encoding.

9The threading model got simpler

Deleted: the entire background-image thread and its condition_variable sleep dance, plus two mutexes (bgImageLoaderMutex, adviceMutex). Now: one std::jthread weatherLoaderThread and one std::mutex weatherMutex guarding a single WeatherState struct.

  • std::jthread (C++20) is a "joining thread": its destructor auto-requests a stop and joins. The std::stop_token parameter is how the loop exits (while (!stopToken.stop_requested())).
  • Single struct behind one mutex. Old code held weather and advice in two separately-locked strings updated at different times — a window for inconsistency. New code fills a local WeatherState, then does one std::scoped_lock and assigns the whole struct. Either you see the complete new weather+advice, or the old — never a mix. This is the "publish a consistent snapshot" pattern.
  • Reading side mirrors it: Render copies the whole struct out under the lock into a local w, then unlocks and draws. Hold the lock as briefly as possible — copy out, then do slow rendering unlocked, so the network thread never stalls the UI.
  • std::scoped_lock (C++17) standardized over the old std::lock_guard; both auto-unlock via RAII. Note the throwaway local std::mutex m; exists only because condition_variable_any::wait_for needs a lock to wait on — it protects nothing, just enables an interruptible sleep.

FetchAdvice extracted: the inline LLM-calling code is now its own method that simply returns the advice string (or a basicAdvice fallback). The fetch loop now reads as advice = FetchAdvice(…) instead of 60 lines of nested try/catch — the refactor's clearest readability win. It also switched from typed structs + NLOHMANN_DEFINE_TYPE_NON_INTRUSIVE to inline j.at("choices").at(0)… navigation.

Gotcha — .at() vs []

With nlohmann::json, .at("key") throws if the key is missing, whereas operator[] silently inserts a null. Because parsing runs inside try/catch (std::exception), a malformed API response throws, gets logged, and leaves ok = false — a safe failure. Using [] here could mask bad data.

10Drawing primitives

New helpers drawIcon, fillRect, fillCircle, drawGradient. Two build vertex/index arrays for SDL_RenderGeometry:

void fillCircle(float cx, float cy, float r, Col c) {
  constexpr int seg = 20;
  SDL_Vertex v[seg + 1];  int idx[seg * 3];
  v[0] = {{cx, cy}, fc, {0, 0}};       // center vertex (a "fan")
  for (int i = 0; i < seg; ++i) {
    float a = (float)i / seg * 2.0f * (float)M_PI;
    v[i + 1] = {{cx + std::cos(a)*r, cy + std::sin(a)*r}, fc, {0, 0}};
    idx[i*3] = 0; idx[i*3+1] = i+1; idx[i*3+2] = (i+1) % seg + 1;
  }
}
  • A filled circle is a triangle fan: one center vertex plus 20 rim vertices → 20 triangles, each (center, rim[i], rim[i+1]). The (i+1) % seg + 1 wraps the last triangle back to the first rim vertex to close the circle. A missing modulo leaves a pie-slice gap.
  • SDL_Vertex uses normalized SDL_FColor (0.0–1.0), hence c.r / 255.f — the same convention clash from §4, converted at the boundary.
  • SDL_Vertex v[seg + 1]; is a fixed-size stack array (compile-time constant size). Cheap, no heap. The gradient does the same with 4 corner vertices — top two colored ct, bottom two cb, and SDL interpolates the gradient across the quad for free.

11Render restructured into named draw methods

void Render() {
  std::tm tm = localNow();
  float f = dayFactor(tm);
  bool isDay = f >= 0.5f;
  Palette p = mixPalette(f);
  WeatherState w; { std::scoped_lock lock(weatherMutex); w = weather; }

  drawGradient(p.bg0, p.bg1);
  DrawDate(tm, p);
  DrawTime(tm, p);
  DrawWeatherStrip(w, isDay, p);
  DrawRain(w, p);
}

The new Render reads like a table of contents — each DrawX is self-contained. Worth noticing inside them:

  • Blinking colon without re-rendering: SDL_GetTicks() % 2000 gives a 0–2000 ms sawtooth; a cosine turns it into a smooth pulse used as the colon's alpha. Because color/alpha apply at draw time (§7), the pulse is free every frame.
  • Absolute layout via Config baselines replaces the old relative chaining. DrawWeatherStrip walks a cursor x left-to-right (x += lTempNum.w + 6.0f; …) — predictable, with dividers as 1px fillRects.
Gotcha — toupper and signed char

c = (char)std::toupper((unsigned char)c); — std::toupper takes an int that must be representable as unsigned char (or EOF). Passing a plain char that's negative (bytes ≥ 128, common in UTF-8) is undefined behavior. The (unsigned char) cast is the standard-mandated fix. It only upper-cases ASCII — fine, since date strings are English now.

12Screenshot mode & the main loop

shotPath = SDL_getenv("APP_SHOT");
if (const char *sf = SDL_getenv("APP_SHOT_FRAME")) shotFrame = SDL_atoi(sf);
// ...
SDL_AppResult Iterate() {
  Render();
  if (shotPath && ++frameCount >= shotFrame) return SDL_APP_SUCCESS;
  SDL_Delay(16);
  return SDL_APP_CONTINUE;
}

If APP_SHOT=path.png is set, the app renders shotFrame frames, saves a PNG (SDL_RenderReadPixels + IMG_SavePNG), and exits with SDL_APP_SUCCESS — the headless-verification hook. SDL_AppResult is SDL3's callback convention: CONTINUE keeps looping, SUCCESS exits cleanly.

The old UpdateTiming/deltaTime/fps machinery is gone because nothing animates with a real delta-time anymore; a flat SDL_Delay(16) (~60 FPS) suffices. Also, the SDL callbacks at the bottom dropped their unused parameter names — SDL_AppInit(void **appstate, int, char *[]). An unnamed parameter says "I must match this signature but don't use this argument," silencing warnings. A new ESCAPE-to-quit handler was added in SDL_AppEvent.

The recurring lesson across the whole commit: do expensive work only when inputs change, keep locks short, use RAII (SdlPtr) so C resources can't leak, and let the type system (scoped enums, move-only pointers, constexpr) catch mistakes at compile time. The two genuinely subtle spots to keep an eye on are the 0–255 vs 0.0–1.0 color convention and the UTF-8 / toupper((unsigned char)) handling — both handled right here, and both classic beginner bug sites.
